# 가변폭 — 조사와 계획

`風雨来記3` 한글화(`f:/dev-furaiki3/furaiki3-l10n`)에서 같은 문제를 이미 뚫었다.
**아키텍처는 완전히 다르지만 방법은 그대로 옮겨진다.** 그쪽 문서
`docs/engine/font-format.md` §5 와 `docs/localization-worklog.md` §2 가 원본이다.

## 우리 쪽에서 확인한 것 (2026-08-08)

전각 격자가 고정이라는 것을 **인게임으로 확정**했다. `HANYOU` 창 ３１２ 에 ASCII 를
넣어 보았다.

```
Hi, there! I'm testing th        ← ２５글자에서 잘림
iiii mmmm WWWW ....  0123        ← ２５글자에서 잘림
```

  * `iiii`·`mmmm`·`WWWW`·`....` 네 덩어리의 **길이가 같다.** 반각 글리프는 １２px 로
    좁게 그려지지만 자리는 전각 하나를 그대로 먹는다 → **펜 전진은 고정 피치**
  * 두 줄 다 정확히 **２５글자**에서 잘렸다 → 상한은 픽셀이 아니라 **글자 수**다
    (레코드 배열 `obj+0x84`~`0x213` = ２５×１６B, [MTG-TIMING.md](MTG-TIMING.md))

실험 스크립트는 `translation/src/_exp_propwidth.py` 에 남겨 두었다
(`--revert` 로 되돌린다).

## ★ 그래서 우리는 **미관만** 얻는다

`風雨来記3` 는 픽셀 폭으로 줄이 접혀서 가변폭이 곧 용량이었다. 우리는 다르다.
**한 줄 ２５글자 상한은 레코드 개수 제한이라 폭과 무관하다.** 공백을 좁혀도
２６번째 글자는 여전히 안 그려진다.

앞서 이 저장소에서 "공백을 좁히면 줄당 ２~３글자를 번다" 고 적었던 것은 **틀렸다.**

얻는 것은 하나뿐이지만 작지 않다 — **한글 어절 사이가 전각(２４px)이면 성기다.**
`風雨来記3` 는 셀 ２５ 에서 공백을 **６px** 로 줬다. 그 차이가 글꼴의 인상을 바꾼다.

## 그대로 옮겨지는 것

### 폭의 출처

IBM Plex Sans KR 의 실제 advance. 우리도 같은 글꼴을 쓴다. 우리 코드페이지
１,０４４자를 재 보니 **한글 음절은 전부 같은 폭**이었다(`@25px` 에서 ２２px) —
`風雨来記3` 쪽 표(셀 ２５ 에서 한글 １,３６４자가 전부 ２０)와 성질이 같다.

즉 **한글끼리는 한 픽셀도 안 줄어든다.** 실익은 공백·문장부호·라틴·숫자에 있다.

| | 셀 ２５ 기준 (`風雨来記3` 실측) |
|---|---|
| 한글 음절 | ２０ |
| 공백 | **６** |
| `.` `,` | ６ |
| 숫자 | １３ (tabular) |
| `m` | １９ · `M` `…` １８ · `%` ２１ |
| 전각 기호 `「」『』、。・` | ２５ (미해결 — 잉크는 ５~７px 인데 칸을 다 먹는다) |

### 구현 얼개

슬롯 번호로 바로 인덱싱하는 **１바이트 폭 표**를 새 PE 섹션에 두고, 렌더러의
전진 계산 자리에 훅을 걸어 표를 조회하게 한다. 밴드(구간 비교 체인)로도 되지만
`風雨来記3` 는 결국 표로 통일했다 — 밴드는 "슬롯 순서 = 폭 오름차순"을 요구해서
**글자를 하나 더할 때마다 배정이 전부 밀린다.** 우리는 코드페이지가 계속 자라므로
처음부터 표로 간다.

### ★ 글리프를 왼쪽 정렬로 다시 그려야 한다

지금 `hangul.render_glyph` 는 잉크를 셀 **가운데**에 놓는다.

```python
x = (24 - (box[2] - box[0])) // 2 - box[0]      # ← 가운데 정렬
```

전진폭을 좁히면 가운데 정렬된 잉크가 **자기 칸을 벗어난다**(`風雨来記3` §6 이
같은 함정을 적어 두었다). 펜 원점(좌측) 정렬로 바꾸고 폰트 전체를 다시 구워야
한다. 기준값: 그쪽 ２５px `.` `,` 는 잉크 x １..４ / 전진폭 ６ 이다.

### 되돌릴 수 있게 만든다

`風雨来記3` 는 훅마다 `on` 스위치를 두고 화면 단위로 켰다. 우리도
`emulator_fixes` 처럼 설정 한 줄로 끄고 켤 수 있어야 한다 — 대사창만 켜고
가이드북·메뉴는 순정으로 두는 것이 첫 목표다.

## 우리에게만 있는 벽

`風雨来記3` 는 x86 단일 exe 였다. 우리는 **SH4 · WinCE · DLL 여러 개**다.

```
TRFFONT.DLL   CTRFFont::DrawChar 0x10001240 — 폭을 돌려주지 않는다(에필로그 확인)
KITAE.DLL     대사창.  TRFFONT 를 임포트하지 않고 클래스 이름으로 찾아 가상 호출
TRFGUIDEMAP   가이드북
KITACMDMENU   커맨드 메뉴·선택지
```

전진을 계산하는 주체가 **모듈마다 따로**다. 나쁜 소식이자 좋은 소식이다 —
한 곳을 고쳐 전부 바꿀 수는 없지만, **대사창만 고쳐도 다른 화면이 안 깨진다.**

### ★ 규명 끝 — 글자 엔진은 `TRFSTRINGS.DLL` 이다 (2026-08-09)

내내 `KITAE.DLL` 을 뒤졌던 것이 헛수고였다. `TRFSTRINGS` 를 **폰트 데이터 덩어리로만**
보고 지나쳤는데, 이름 그대로 TRF **Str**ings — 글자 엔진 본체다(`.text` ４６KB).
[MTG-TIMING.md](MTG-TIMING.md) 가 인용한 주소가 전부 여기서 맞아떨어진다.

```
0x10007C30   mov #25,r3 · cmp/gt · mov #25,r2     한 줄 25글자 상한 (화면과 일치)
0x10007524   BuildTiming 프롤로그
0x100076CC   토크나이저 프롤로그
```

모든 DLL 이 `ImageBase 0x10000000` 이라 **주소 범위만으로는 모듈을 가릴 수 없다.**
클래스 이름(`ITRFStrTiming`)으로 갈라야 한다 — `TRFFONT`·`TRFKernel` 에는 없다.

### 글자 루프 `0x10003558`~`0x100035C8`

```
0x1000357a  mul.l  r11,r1        ; r1 = @(20,r15) 레코드 보폭 × r11(글자 인덱스)
0x10003582  add    r4,r8         ; r8 = 레코드 배열 + 인덱스*보폭  → 이번 글자의 레코드
0x100035a8  mov.l  @r9,r6        ; 폭을 그리기 호출에도 넘긴다
0x100035b4  mov.l  @r9,r4        ; ★ 폭 읽기 — 즉치가 아니라 객체 필드
0x100035b8  add    @(52,r10),r4  ; + 자간
0x100035be  sub    @(48,r10),r4  ; − 보정
0x100035c6  bt/s   0x10003558    ; 다음 글자
0x100035c8  add    r4,r12        ; ★ 펜 X 전진
```

  * `r13` 글꼴 객체(가상 호출) · `r11` 글자 인덱스 · `r12` **펜 X** · `r8` 이번 레코드
  * **`@r9` 는 모든 글자에 같은 값**이다 = 셀 고정 폭. `add #24` 같은 즉치를 아무리
    찾아도 안 나온 이유다

### 그래서 (가) 였다

앞서 갈랐던 두 갈래 중 **글자마다 폭을 더해 가며 미는 형태**다. 열 번호 × 고정폭이
아니다. `0x100035B4` 의 `mov.l @r9,r4` 를 **슬롯→폭 조회**로 바꾸면 된다 — 훅 하나다.
`風雨来記3` 의 `add esi,eax` 와 같은 자리이고, 우리는 `add r4,r12` 다.

게다가 `TRFSTRINGS.DLL` 은 **폰트 글리프를 넣느라 매 빌드 이미 패치하는 파일**이다.

### ★ 규명 끝 — 코드는 레코드에 없다 (2026-08-14, 인게임 성공)

레코드에 코드가 있으리라 보고 `@(8,r8)` 을 썼다가 화면이 들쭉날쭉했다. **틀렸다.**

갈라낸 방법이 요점이다. `+8` 이 코드인지는 화면으로 확인할 방법이 없다 — 코드는
값이 제각각이라 폭이 이상해도 표가 틀렸는지 자리가 틀렸는지 모른다. 대신 **`+12`
가 바이트 길이(반각 1·전각 2)인지** 물었다. 값이 두 가지뿐이라 화면만 봐도 안다.
`폭 = @(12,r8) × 8` 로 구워 보니 **모든 글자가 똑같이 ２４ 안팎**이었다(간격 ~197px).
길이였다면 반각·전각이 갈렸어야 한다. 그러므로 레코드는 문자 정보가 아니라
**텍스처 사각형**이다.

객체 배치는 이렇다. 레코드 배열이 폭 배열 바로 앞에서 정확히 끝난다.

    obj+0x0054  레코드  25글자 × 320 (= 20크기 × 16B)
    obj+0x1F94  폭 배열 (크기별)        ← 루프의 `@r9`. 글자와 무관하니 고정폭이었다
    obj+0x1FF4  현재 인덱스
    obj+0x1FFC  ★ 코드 배열 포인터 (u16)
    obj+0x2004  글자 수

코드는 **별도 u16 배열**에 있고, 엔진 자신이 여섯 군데에서 같은 관용구로 읽는다
(`0x100033BE`·`0x100033EE`·`0x100031C4`·`0x10002F54`·`0x100031F8`·`0x10003D12`).

    mov.l  @(0x1FFC,obj),r0    ; 코드 배열
    shll   idx                 ; ×2
    mov.w  @(r0,idx),r1        ; u16 코드
    extu.w r1,r1
    shad   #-12,r1             ; 상위 니블로 분류 → **cp932 그대로**다

훅 자리에 `r10`(객체)·`r11`(인덱스)이 다 살아 있어서 스텁이 직접 꺼낸다. 단
`add #1,r11` 은 **코드를 읽은 뒤에** 둬야 한다 — 먼저 올리면 한 글자씩 밀린다.

### 하위표 우선순위 — 디스크 여유가 곧 품질이다

익스텐트 여유가 1,024B 뿐이라 하위표는 두 장이다. 그래서 **어느 페이지에 주느냐**가
품질을 정하는데, 처음엔 "폭 종류가 많은 순"으로 줬다가 URL 용 ASCII 페이지가 한 장을
가져갔다. 정작 공백이 든 페이지가 대표값으로 뭉개져 **공백 9 → 13, `。` 10 → 13**
이 됐다. 본문에서 １９,０００번 나오는 공백이 ２１７번 나오는 URL 에 밀린 것이다.

지금은 공백이 든 페이지와 전각 숫자·라틴이 든 페이지에 준다 — 가변폭으로 얻는 것이
거기 다 있다. 한글 페이지(`0x9B`·`0xE1`~`0xE3`·`0xED`·`0xEE`)는 전부 ２２ 단일값이라
직접값 한 바이트로 끝난다.

### 진단 모드 두 가지를 남겨 두었다

`font_variable` 에 넣는다. 다음에 막히면 순서대로 쓴다.

    "flat"   표를 안 보고 무조건 22 — 사슬(훅→징검다리→스텁→복귀)만 시험한다
    "len"    레코드 `+12` × 8 — 레코드가 무엇인지 화면으로 가른다

**값이 두 가지뿐인 것을 물어야 화면으로 갈린다.** 이번에 배운 요령이다.

## 옛 기록 — 지금 막힌 곳 (해소됨)

`KITAE.DLL` 에서 펜을 미는 자리를 못 짚었다.

  * `add #24` / `add #12` 같은 즉치가 어느 DLL 에도 없다
  * 문자열을 바이트로 훑는 흔한 루프 형태도 아니다(후보 ０곳)
  * [MTG-TIMING.md](MTG-TIMING.md) 가 적어 둔 `0x100035B4~0x100035C8` 은 열어 보니
    `KITAE` 에선 소멸자 루프, `KITAHEGEL` 에선 스택 푸시였다 — **그 인용은 틀렸다**

`風雨来記3` 는 전진을 싣는 명령(`add esi,eax` 등)을 훑어 찾았다. 우리는 가상
호출에 막혔으므로 **동적으로 잡는 것이 빠르다.**

    Flycast 의 GDB 스텁(emu.cfg `Debug.GDBEnabled`)으로
    DrawChar 진입점에 중단점 → 호출자(pr 레지스터)를 역추적한다.

## 순서

1. **Flycast GDB 로 `DrawChar` 호출자를 잡는다** ← 여기가 갈림길
2. 호출자에서 x 를 누산하는지, 열 번호 × 폭으로 내는지 본다
   * 누산이면 → 표 조회로 바꾸는 훅 하나
   * 좌표 직접 계산이면 → 배치를 다시 쓰는 일. 재검토
3. 슬롯→폭 표를 만든다(`FONT.slot_width()` 격의 단일 출처 하나)
4. 글리프를 **왼쪽 정렬**로 다시 굽는다
5. 새 PE 섹션에 표를 싣고 훅을 건다 — 섹션 추가는 검증돼 있다
   (`.reloc` **앞**에 놓아야 한다. 뒤에 놓았다가 오디오가 깨진 적이 있다)
6. 대사창만 켜고 인게임 확인 → 가이드북·메뉴는 나중에

## `風雨来記3` 에서 미리 배우는 함정

  * **재배치.** 손으로 넣은 절대주소는 로드 때 안 밀려 죽는다. 우리는 `.reloc` 검증
    경로가 이미 있으니 그걸 쓴다
  * **플래그.** 훅 앞의 `cmp` 결과를 훅 뒤가 쓰는 자리가 있었다. 스텁이 플래그를
    건드리면 안 된다
  * **한 화면을 두 번 그리는 곳이 있다.** SNS 는 본문·이름을 각각 두 번 그려서
    한쪽만 켜면 넓게 그려졌다가 줄어들었다. 대사창도 클릭 대기 마커 등으로
    두 경로일 수 있다
  * **켜면 안 되는 자리가 있다.** 공용 경로를 켰더니 엉뚱한 화면이 바뀌었다
