# 에뮬레이터 버그와 우회 패치

이 게임은 **Windows CE 타이틀**이다. 디스크 부트스트랩이 그렇게 말한다.

```
부트 파일    0WINCEOS.BIN
주변기기     0x00199801   ← 최하위 비트 = WinCE
대응 지역    J
```

WinCE 게임은 SH4 의 MMU 를 실제로 쓴다. 대부분의 드림캐스트 게임은 안 쓰기 때문에
에뮬레이터들이 오래도록 MMU 를 대충 넘겼고, 그래서 WinCE 타이틀은 지금도 가장
까다로운 부류다. **여기 적는 것은 게임의 버그가 아니라 에뮬레이터가 못 하는 일이고,
우리가 디스크 쪽에서 피해 가는 방법이다.**

## ★ 규칙 — 원본에서 재현되는지 먼저 확인한다

번역 때문에 생긴 문제와 에뮬레이터 문제는 증상이 똑같이 보인다. 아래 [선택지
게이트](#선택지-게이트--선택-상자가-안-그려진다) 를 쫓을 때 창 테이블·EB·타이밍·음성
표를 다 뒤지고 나서야 원본에서도 같다는 걸 알았다. **순서를 뒤집지 말 것.**

1. **패치하지 않은 원본 디스크**에서 같은 자리를 확인한다
2. **다른 에뮬레이터**에서도 확인한다 (redream ↔ Flycast)
3. 둘 다 재현되면 여기 적고, 우회 패치는 `emulator_fixes` 아래에 둔다

우회 패치는 번역과 섞지 않는다. 켜고 끌 수 있어야 하고, 끄면 원본과 같은 바이트가
나가야 한다.

## 선택지 게이트 — 선택 상자가 안 그려진다

**증상.** 선택지가 나와야 할 자리에서 대사만 떠 있다가, ２~３초 뒤 아무것도 고르지
않았는데 고른 것처럼 진행된다. 상자가 화면에 없으니 고를 수가 없다.

**확인 (2026-08-08).** redream v1.5.0-1231 · Flycast 2.6 **둘 다**, 그리고 **패치하지
않은 원본 디스크에서도** 재현된다. 번역과 무관하다.

### 무엇이 갈랐나

선택지를 여는 `0x73`/`0x74` 앞에 두 갈래가 있다.

| 앞선 옵코드 | 곳 | 결과 |
|---|---|---|
| `0x2E` · `0x46` | 524 | 뜬다 |
| `0x6E`\|`0x6F` · `0x24` · `0x42` · `0x2E` · `0x46` | 508 | **안 뜬다** |

`0x6E`/`0x6F` 는 `<u16 대기 프레임> <u16 대상 ID>` 를 받는다 — 프레임은 １２０·１８０·
２６０(２~４．３초), ID 는 `0x22`~`0x45`. 이 값이 곧 관찰된 멈춤 시간이다. **타이머는
정상으로 돈다. 그리기만 빠진다.**

게이트는 음성과 강하게 붙어 다닌다.

```
0x6E/0x6F 있음 · 앞 창 유성   495곳
0x6E/0x6F 있음 · 앞 창 무성    13곳
0x6E/0x6F 없음 · 앞 창 무성   300곳
0x6E/0x6F 없음 · 앞 창 유성    50곳
```

９７% 가 유성 창 뒤다. 다만 **음성이 기준은 아니다** — `KOTORI_01` 창４５ 는 앞 창이
무성인데도 게이트가 걸려 있고 증상이 난다. 기준은 게이트 옵코드 자체다.

`0x2E` 의 오퍼랜드(４ 대 ８)는 원인이 아니다. `0x2E 4` 는 ６１３곳이 쓰는 가장 흔한
값이고 그중 다수가 멀쩡히 뜬다.

### 우회

`0x6E`/`0x6F` 다섯 바이트를 `0x00` 으로 덮는다 →
[`kitae/build/ebgate.py`](../kitae/build/ebgate.py)

```
전  0x6E b4 00 2e 00 · 0x24 · 0x42 · 0x2E · 0x46 · 0x73
후  0x00 ×5          · 0x24 · 0x42 · 0x2E · 0x46 · 0x73
```

안전한 근거 셋:

- `0x00` 은 전 대본에 **２１,００３곳** 나오는 문장 구분자다(`0x6B` 뒤에만 ６,９７６곳).
  다섯 바이트를 덮으면 빈 문장 다섯 개가 된다.
- 게이트만 빠진 이 형태가 **원본에 이미 ９곳** 있다(`KAORU` 창９, `KOZUE` 창２７９ 등).
  엔진이 처리하는 형태다.
- 길이가 그대로라 점프 목적지도 `tail_off` 도 움직이지 않는다.

**결과 (2026-08-08 인게임 확인).** 선택지가 뜬다. ５０８곳 전부에 적용된다.

### 잃는 것

시간 제한이 사라진다. 원래 ２~３초 안에 못 고르면 기본값으로 넘어갔는데 이제는 고를
때까지 기다린다. **"뜸을 들이는 것 자체가 선택"인 장면이 있다면 거기서 멈춘다.**
그런 자리를 만나면 그 창만 게이트를 남기도록 예외를 두면 된다.

지금은 상자가 안 그려져 **항상** 기본값으로 넘어가는 상태이므로, 고를 수 있게 되는
쪽이 낫다고 보고 켜 둔다.

### 끄기

```json
"emulator_fixes": { "choice_gate": false }
```

끄면 EB 는 원본 바이트 그대로 나간다.

## 미해결

### 가라오케에 들어가면 리셋된다

**증상.** 가라오케 화면에 들어가는 순간 리셋된다.

**상태.** 원인 미상. 우리가 그 화면에서 바꾼 것은 `TRFKARAOKE.DLL` 의 조작 설명 두
줄뿐이었고(여유 ８ B 로 빠듯하게 제자리에 들어갔다), 지금은 **되돌려 원본 그대로**
나간다. 가사(`歌詞.SMF`·`歌詞.EB`)는 애초에 손댄 적이 없다 — 디스크 대조로 확인했다.

되돌린 뒤에도 리셋되는지 아직 확인 못 했다. 그래도 리셋된다면 다음을 의심한다.

- 폰트(`TRFSTRINGS.DLL`). 가사가 쓰는 글리프 칸을 우리가 한글로 덮었을 수 있다.
  `used_cells` 의 예약 목록은 **대사**를 훑어 만든 것이라 가사 쪽은 안 세었다.
- WinCE 특유의 화면 전환. 이쪽이면 위 규칙대로 원본에서 먼저 재현해 봐야 한다.

되살릴 오프셋은 [`translation/src/minigames.py`](../translation/src/minigames.py) 의
`TRFKARAOKE` 블록에 주석으로 남겨 두었다.

## 에뮬레이터 설정

디스크는 `대응 지역 J` 인데 두 에뮬레이터 다 USA·English 로 잡혀 있었고, 실기 BIOS
없이 HLE BIOS 로 돌고 있었다. WinCE 타이틀은 부팅 과정에서 BIOS 를 더 깊이 쓰므로
일반 게임보다 잘 어긋난다. 원인 모를 증상을 쫓기 전에 아래를 먼저 맞춰 둘 것.

| | 맞춰야 할 값 |
|---|---|
| 지역 | Japan |
| 언어 | Japanese |
| BIOS | 실기 `dc_boot.bin` (HLE 아님) |
| Flycast `aica.DSPEnabled` | `yes` |
| redream `frameskip` | 끔 |
