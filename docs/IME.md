# 한글 입력기(IME) — 이름 입력 화면 (TRFNAMEIN) 조사 결과와 설계

목표: 이름 입력 화면에서 두벌식 자모로 한글 이름을 넣게 한다(2026-09-24 사용자 결정, 방식 A).
옵션 `ime`. 1단계(`kitae/build/ime.py`, 글꼴·격자·표)와 2단계(`kitae/build/imestub.py`, PutChar 훅 +
오토마타 SH4 스텁)가 들어갔고, `tools/ime_emu_test.py`(SH4 미니 에뮬레이터)로 파이썬 참조와 대조해 35 사례
통과. **인게임 확인은 아직.** 아래 조사 사실은 정적 역어셈블 + Flycast 라이브(런타임 베이스 0x018E0000).

## 화면 구조

- 왼쪽 아이콘 `漢字 / かな / カナ / 英数 / 決定`, 위쪽 이름 바(`성 ____ 이름 ____`), 아래 격자.
- **격자 = 행 우선 6행×15열**(5칸 블록 3개, x=157·311·465). `index = this+0x124*15 + this+0x120`.
  かな 모드는 `0x10015454`(90×u16), カナ는 `0x10015508`을 `0x10004bac`이 `this+0x240`에 복사해 그린다.
  漢字 모드는 45칸 가나 읽기표 `0x100150ac`(3블록×15)로 읽기를 고르고 한자 후보를 `this+0x240`에 76칸씩 페이지로 만든다
  (`0x100014b8`, 페이지 `this+0x7fa`/수 `this+0x7f8`).
- 이름 바는 **u16 배열 10칸 `this+0x158`**(성 0~3, 이름 4~9), 커서 `this+0x118`(0~9, 9에서 멈춤).
  cp932 바이트열 사본 `this+0x128`(성, 16B)·`this+0x140`(이름, 12B)은 `0x10003afc(this)`가 배열에서 다시 만든다.
  확인 창용 문자열은 `obj+0x18` 인터페이스의 `0x10003a08`이 `obj+0x820`(성)·`obj+0x838`(이름)에 만들어 돌려준다.
- 이름 입력 태스크 객체: 크기 0x8d8, 생성자 `0x100052a0`, vtable `0x1001483c/+4 0x10014854/+0x18 0x1001488c/+0x1c 0x100148a4`,
  등록 슬롯 `.data 0x10016028`. 라이브에서 `8c7cae74`.
- 이름을 안 넣고 확정하면 42쌍 샘플표(`0x10015c44`→`0x10015d94`)에서 무작위 한 쌍을 `0x10016060/64` 슬롯에 넣는다.

## 글자 넣기 — 훅 자리

**`0x10001000` = PutChar(this, code, advance)**:
```
cursor = this+0x118
this+0x158[cursor] = code (u16)
0x10003afc(this)                       ; 바이트열 재생성
if advance: cursor++ (>9 면 9 로 두고 1 반환), this+0xcc = this+0xd0 = 0, 0x100018dc(this)
```
호출자(복귀 주소 PR):
- **A 커밋** `0x10001352` → PR `0x10001358`: `PutChar(this, this+0x240[index], 1)`
- **X 삭제** `0x10002c1c`(PR `0x10002c26`)·`0x10002c34`(PR `0x10002c3e`): 커서 칸이 빈칸이면 커서를 물리고, `PutChar(0x8140, 0)`
- **포커스 이동** `0x10001a52`(PR `0x10001a5c`): `PutChar(0x8140, 0)`

프롤로그(`0x10001000~0x1000100e`)가 r8~r11·pr 을 밀고 `r15 -= 16` 하므로 `0x10001010` 16B 를 `hook16` 으로 걸면
스텁 진입 시 r8=this, r5=code, r11=advance, 호출자 PR = `@(16,r15)`. 에필로그 `0x10001050` 으로 돌아오면 된다.
`0x10003afc`·`0x100018dc` 는 r8~r11 을 보존한다. 반환값은 세 호출자 모두 안 쓴다.

## 공간

- TRFNAMEIN 디스크 여유 **0 B**(44섹터 딱, 섹터 경계까지 512B) — 섹션 증설은 512B 가 한계.
- 케이브: `.text` 꼬리 434B · `.pdata` 378B · `.data` 꼬리 474B(uipatch 재배치가 쓸 수 있음, 빌드 때 검증) · `.rdata` 꼬리 383B.
- **`.rdata`(60KB)는 256B 슬롯짜리 클래스 이름 문자열 표**(`ITRFInterface`, `CTRFImageDraw` …, 블록 0~229). NUL 뒤는 안 읽는다
  → 각 블록 `[32,256)` 이 빈 공간(≈51KB). 블록 230~234 는 vtable 이라 제외. uipatch 는 `.rdata` 를 건드리지 않는다(빌드본 동일).

## 셀 예산

한글용 빈 칸 3,150(기호·예약 제외, 69개 연속 구간). 완성형 2,350자를 다 구워도 799칸 남는다.
자모 40개(초성 19 + 중성 21, 호환 자모 U+3131~)는 기호 페이지에 연속으로 둔다. 글리프는 Plex 에서 정상 렌더(확인).
`assign_josa` 는 `jong_group` 이 None 인 자모를 재배정 대상에서 빼므로 자모용 배정을 따로 넣어야 한다.

## 구현

### 1단계 — 빌드 쪽 (`ime.py`)

1. かな 표 90칸(`.data 0x10015454`)을 자모 셀로 바꾼다. 격자·선택 코드는 그대로 따라온다(초성 왼쪽 블록 4행,
   모음 가운데·오른쪽). 글꼴에는 완성형 2,350 + 무받침·ㄹ받침 각 399 + 자모 40 을 더 굽는다(`ime.chars()`).
   자모 40 셀은 `hangul.contiguous_jamo` 가 연속으로 잡는다 — 스텁이 `code − 첫 셀` 로 판별한다.
2. 음절→셀 **11,172×u16 직접 표**를 `.rdata` 블록 0~174 의 `[32,160)` 에 64칸씩 흩어 넣는다:
   `주소 = 0x10006020 + (idx>>6)·256 + (idx&63)·2`. 없는 음절은 0.

### 2단계 — 훅과 스텁 (`imestub.py`)

`0x10001010` 16B(`hook16`) → 새 PE 섹션 `.kime`(512B, `pesection.add`, `.reloc` 앞 VA `0x10018000`) 의 본체
≈504B. TRFNAMEIN 은 디스크 여유가 512B 뿐이라 섹션은 이 크기가 한계고 본체도 딱 맞게 들어간다(리터럴 8개 포함).
헬퍼(SCAN·DOPUT·COMMIT·GLYPH, 160B)는 `.rdata` 블록 176 꼬리, 표(176B)는 블록 175 꼬리, 상태 4B 는 `.data`
꼬리 끝 `0x100161fc`. 모두 거리 리터럴로 찾아 재배치가 필요 없다. 파일은 89,600 → 90,112B 로 커진다.

흐름(스텁 진입 시 r8=this, r5=code, r11=advance, 호출자 PR=@(32,r15)):

1. 호출자 PR 이 스텁 헬퍼 DOPUT 의 복귀점이면 **재귀** — 원본 8명령의 결과(r0·r2·r9·r10)만 만들고 `0x10001020`
   으로 돌아가 원본 본문이 글자를 쓴다. 글자 쓰기는 이렇게 PutChar 를 다시 불러 커서 전진·클램프·`0x10003afc`·
   `0x100018dc` 를 원본 그대로 태운다.
2. code 가 자모면 오토마타. 상태 `{~cursor, 초성, 중성, 종성}` — **커서는 `~cursor` 로 저장**해 로더가 채우는 0 이
   곧 "쉼"이다(그냥 두면 0 이 "0번 칸에서 「가」 조합 중"으로 읽혀 첫 키가 「각」이 됐다).
3. code 가 빈칸이고 PR 이 X 삭제(`0x10002c26`/`0x10002c3e`)이며 이 칸을 조합 중이면 **자모 하나만** 뺀다
   (겹받침 → 홑받침 → 없음, 복모음 → 앞 모음, 초성만 남으면 빈칸 + 상태 버림).
4. 그 밖(A 로 고른 빈칸·한자·가나, 포커스 이동)은 상태를 버리고 원본대로.

오토마타가 처리한 뒤엔 `r5 = 지금 칸의 값, r11 = 0` 으로 1 과 같은 길을 지나 원본이 같은 값을 다시 쓰게 한다
(에필로그로 뛰는 것보다 짧다). 규칙은 `ime.Composer` 와 같다: 겹받침 결합·복모음·도깨비불(받침이 다음 초성으로).

**없는 음절.** 받침을 붙인 결과가 표에 없으면(「철」+ㅅ 의 「첧」— 겹받침 중간 상태에 흔하다) 지금 칸을 확정하고
그 자음을 새 초성으로 삼는다(→「철수」). 무받침·ㄹ받침은 전부 굽기 때문에 모음 경로는 실패하지 않는다.
`Composer(baked=…)` 가 같은 규칙.

### 검증

`python tools/ime_emu_test.py` — 패치된 TRFNAMEIN 을 SH4 미니 에뮬레이터에 올려 PutChar 를 실제로 부르고
(게임 함수 둘은 rts 로 친다) 파이썬 참조와 이름 칸·커서를 대조한다. 조합·삭제·가나 섞기·칸 끝(9) 35 사례.

### 알려진 한계

- 조합 중인 칸에서 다른 모드(한자·가나) 글자를 고르면 그 칸을 덮어쓴다(커서가 아직 그 칸이라 — 원본 동작).
  스텁 예산(512B)이 꽉 차 "먼저 확정하고 넣기"는 못 넣었다.
- 아이콘은 아직 `かな` 다(3단계).
- 세이브 호환: 조사 엔진과 같은 이유로 코드페이지가 바뀌면 옛 세이브 이름이 깨진다 — 배포 전에 넣는다.
