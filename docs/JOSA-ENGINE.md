# 동적 조사(助詞) 엔진

`&主人公&`·`&主人公名前&`·`&名前&` 은 런타임에 플레이어 이름으로 치환된다. 그 뒤에 한국어
조사를 고정으로 붙이면 이름 **받침**에 따라 절반이 틀린다(「켄는」 vs 「켄은」). 게임 엔진엔
받침 조건 조사가 없으니 텍스트 엔진에 훅을 걸어 런타임에 고른다.

옵션 `josa`(`kitae.config.json`). **POC(은/는 한 쌍) 인게임 확인 완료 — 2026-09-24, Flycast.**

## 핵심 — 받침을 셀 배정 순서에 인코딩 (표 없음)

폰트 셀 배정은 우리가 한다. 한글을 **받침 성질로 3구간 정렬**해 깔면 런타임 판정이
**비교 하나**로 끝난다. 셀코드는 `lead<<8 | trail` 이라 페이지 경계를 넘어 선형 비교가 성립한다.

    배정 순서: [무받침] [ㄹ받침] [기타받침]     (구간 안은 셀코드 오름차순)
    받침 있음 = cell >= B1      은/는·이/가·을/를·와/과·아/야 …
    (으)로    = cell >= B2      무받침·ㄹ받침은 `로`

현 codepage 기준: 무받침 260 · ㄹ받침 148 · 기타받침 864, `B1 = 0x9C8A` · `B2 = 0x9D61`.
경계는 **빌드 산출물**이라 파일로 남기지 않는다 — `hangul.josa_bounds(cp)` 가 매번 계산하고,
세 구간이 실제로 갈리는지 그 자리에서 검증한다(안 갈리면 훅이 조용히 틀린 조사를 고른다).

`hangul.assign_josa()`. **`PAGES` 를 숫자 오름차순으로 돈다** — 원래 순서는 안전한 페이지
선호도라 숫자 순이 아니고, 그대로 쓰면 셀코드가 단조가 아니게 되어 비교가 깨진다.

## 표기 — `{은는}` 마커 한 칸

`widths.JOSA = {"{은는}": ("은", "는")}`. 마커는 `SYMBOL_CELLS` 에 들어가 **셀 한 칸**을 받고,
`hangul.units()` 가 한 단위로 쪼갠다. 그래서 글자 수·타이밍·줄 폭이 조사 한 글자와 똑같아
빌드 쪽에 따로 손댈 게 없다. 글리프는 무받침형(`는`)으로 굽는다 — 훅이 실패해도 글이 읽힌다.

키를 `{받침형무받침형}` 꼴로 감싼 이유는 **조사 철자가 본문에 흔하기 때문**이다. `으로` 를
그대로 마커로 쓰면 평범한 낱말과 부딪친다.

## 훅 — 토크나이저 2바이트 글자 경로

`TRFSTRINGS 0x1000783A` 16B(`hook16`) → `.pdata` 꼬리 스텁 80B(`vwstub.stub_josa`).
`.text`·`.rdata` 꼬리는 가변폭 스텁이 이미 차서 `.pdata` 를 쓴다(SH4 는 읽기 = 실행).

    0x1000783A  shll8 r4 / or r1,r4      ; r4 = lead<<8|trail  ← 스텁이 재현
    0x1000783E  mov.l r4,@(8,r14)        ; 프레임 +8 = code    ← 여기 전에 r4 를 바꾼다
                mov #2,r2 / @(12,r14)    ; len = 2
                mov.l @(20,r15),r13      ; 노드 리스트 헤더
                mov #0,r6 / @(4,r13),r5  ; tail

**직전 글자는 헤더 `+4`(tail)가 그대로 가리킨다** — 리스트를 훑을 필요가 없다(노드를 붙일 때마다
`0x10007A6E` 가 tail 을 갱신한다). 노드 `+8` 이 코드다. 스텁은 `code == 마커` 면
`tail->code >= B1` 로 받침을 보고 `은`/`는` 셀로 바꿔치기한다.

**★ r0 주의.** 훅 바로 앞(`0x10007838`)에서 r0 에 노드 할당 함수(`0x1000851C`)를 싣고 훅 뒤
(`0x1000784A`)에서 `jsr @r0` 한다. `hook16` 이 r0 로 점프하므로 **스텁이 r0 를 되살려야 한다** —
절대주소는 못 쓰니 거리 리터럴로 되짚는다. r1·r2·r3 은 복귀 뒤 전부 다시 세팅되므로 써도 된다.

## ★★ 세이브 호환이 깨진다 — 배포 전에 확정할 것

받침순 재배정은 **한글 셀 100%를 옮긴다**(1,272자 전부). 대사·폰트는 빌드가 다시 만들지만
**세이브에 저장된 이름은 그때 쓰던 셀 바이트 그대로**라 새 코드페이지로 읽으면 깨진다.

    '코' 가 쓰던 0xEEEF → 지금은 미배정 · '치' 0xE1B6 → '했' · '타' 0xE1C6 → '홈'

진행도·플래그는 숫자라 멀쩡하고 이름만 깨진다. **한 번 배포한 뒤 코드페이지를 바꾸면 사용자
세이브가 같은 식으로 깨지므로, 조사 엔진은 배포 전에 넣어야 한다.** 받침 판정을 셀 순서 대신
표로 하면 피할 수 있지만 페이지마다 하위표가 필요해 `.ktrw` 예산(1,024B)에 안 들어간다.

## 남은 일

- **마커는 아직 하나만 된다.** 스텁이 표가 아니라 리터럴 한 벌이라, 둘 이상이면 빌드가 막는다.
  이/가·을/를·와/과·아/야·(으)로 로 넓히려면 스텁을 마커 표 순회로 바꾼다((으)로는 `B2` 비교).
- POC 잔재: `KOTORI_01` 창1.0 테스트 문장, `TRFNAMEIN` 85576(`充`)의 받침 이름 `켄`.
  원문 이름은 전부 모음으로 끝나 받침이 나오지 않으므로 시험용으로 한 칸 바꿔 둔 것이다.

## 곁들여 — 이름 입력 화면은 원래 고정폭이다

이름 입력 안내문은 `CTRFFontTex` 로 텍스처에 굽는 경로(`ITRFImageDraw2`)라 가변폭 훅
(`CTRFMessage`·`CTRFTextOut`)이 하나도 안 걸린다. 조사 작업 중 "가변폭이 사라졌다"고 본 것은
회귀가 아니라 이 화면이 처음부터 그랬던 것이다(2026-09-24 확인).
