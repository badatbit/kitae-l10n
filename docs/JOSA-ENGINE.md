# 동적 조사(助詞) 엔진 — 설계

`&主人公&`·`&主人公名前&` 은 런타임에 플레이어 이름으로 치환된다. 그 뒤에 한국어
조사(은/는·이/가·을/를·와/과·아/야·(이)라고·(이)야·(으)로)를 고정으로 붙이면
이름 **받침**에 따라 절반이 틀린다(「박은」 vs 「츠요시는」). 게임 엔진엔 받침
조건 조사 기능이 없으니, 텍스트 엔진에 훅을 걸어 런타임에 고른다.

## 핵심 착상 — 받침을 셀 배정 순서에 인코딩 (표 없음)

폰트 셀 배정(`assign()`)은 우리가 한다. 한글 음절을 **받침 성질로 3구간 정렬**해
배정하면, 런타임 받침 판정이 **셀코드 비교 하나**로 끝난다. 표도 비트맵도 없다.

    배정 순서:  [무받침]  [ㄹ받침]  [기타받침]      (각 구간 안은 셀코드 오름차순)
    경계:        B1 = 받침 시작(=ㄹ받침 첫 셀)
                 B2 = 으로 경계(=기타받침 첫 셀)

셀코드는 `lead<<8 | trail` 이고 페이지가 `0x9b < 0xe1 < … < 0xee` 라 **선형 비교가
페이지 경계를 넘어 성립**한다. 그래서:

| 판정 | 비교 | 쓰는 조사 |
|---|---|---|
| 받침 유무 | `cell >= B1` | 은/는·이/가·을/를·와/과·아/야·(이)라고·(이)야 |
| 으로 여부 | `cell >= B2` | (으)로 — 무받침·ㄹ받침은 `로`, 그 외 `으로` |

검증(현 codepage, 1116자): 무받침 245·ㄹ받침 132·기타받침 739. 완전 분리 확인
(받침 max < B1 ≤ 받침, 기타받침이 B2 이상). 전 음절 판정 일치.

경계 B1·B2 는 **빌드 산출물**이다(codepage 마다 다름). 훅에 심는다 — 가변폭 폭표를
codepage 에서 뽑아 심은 것과 같은 패턴.

## 구현 조각

### ① assign() 3구간 재배정 + 경계 (`kitae/build/hangul.py`)

지금은 증분 안정(기존 배정 유지)이라 셀이 받침순이 아니다. **전체 재배정**으로
바꾼다: 한글을 `(받침군, 음절)` 로 정렬(무받침0·ㄹ받침1·기타2)해 빈 셀에 오름차순
배정. B1·B2 를 계산해 codepage 와 함께 낸다. cp932 되읽기 불가 셀·게임 예약 셀
제약은 그대로 지킨다. **전체 재배정이라 폰트·전 대사 재굽기가 따라온다.**

### ② 조사 마크업 (대사 원장)

`&主人公&` 뒤에 조사 마크업을 심는다. 후보:

    &主人公&&은는&      →  이름 + (은|는)
    &主人公&&이가&·&을를&·&와과&·&아야&·&이라고&·&이야&·&으로&

토크나이저가 `&…&` 를 건너뛰므로(0x10007b00), 조사 마크업만 특별 처리하게 훅한다.

### ③ 토크나이저 훅 (`TRFSTRINGS.DLL`)

`&` 마크업 핸들러(0x10007b00~)에서, 마크업 내용이 조사 코드면 **직전에 출력한
셀**(=이름 마지막 음절)을 B1/B2 와 비교해 해당 조사 셀을 출력 스트림에 넣는다.
가변폭처럼 `.text` 케이브 스텁 + 상대분기. 직전 셀 접근 가능 여부(출력 버퍼 구조)
확정이 선행 과제.

### ④ 조사 글자 셀 (빌드시 심음)

`은/는/이/가/을/를/와/과/아/야/라/고/으/로` 의 셀도 빌드마다 다르다. 훅이 쓸 셀
값을 빌드시 codepage 에서 뽑아 스텁 표에 심는다.

## 진행 순서 (개념 증명 우선)

1. **①** assign 3구간 + 경계 — 단독 검증(codepage 순서·B1·B2)
2. **③④** 은/는 한 쌍만 훅으로 끝까지 — 인게임에서 「박은/츠요시는」 확인
3. 되면 나머지 조사(이/가·을/를·…·으로)로 확장

## 임시 조치 (엔진 전까지)

받침 뒤따르는 곳이 현재 2곳뿐(둘 다 KOTORI_01):

    w51  &主人公&라고　합니다  →  받침 피해 재작성 (예: 저는　&主人公&입니다)
    w86  &主人公名前&이야       →  받침 피해 재작성 (예: 이름은　&主人公名前&)

`씨`·`군`·`입니다`·`에게` 는 받침 무관이라 그대로 둔다.
