# 한국어 텍스트 문자 처리 명세 (2026-09-18)

사용자가 준 규칙 명세를 받아 다시 쓴 것이다. **[원칙]** 은 사용자가 정한 것, **[추가]** 는
내가 필요하다고 보아 덧붙인 조건이다. 근거 조사는 [work/symbol_survey.md](../work/symbol_survey.md)
(원문·번역문의 문장부호·기호·공백 전수 집계, 갈래별).

## 0. 범위와 용어

- 대상: `translation/**/*.json` 의 `text.ko` (대사·가이드·퀴즈·UI). `ja` 는 건드리지 않는다.
- **셀**: 엔진이 한 글자로 다루는 2바이트 코드. 한글·기호·ASCII 재할당·합자가 모두 셀 하나다.
- **글리프**: 화면에 그려지는 단위. 셀 하나 = 글리프 하나. 글자 수·줄 길이·타이밍은 전부 글리프 수다.
- **마크업**: `@…@`(재생 제어), `&…&`(이름 치환), `%N%`(선택지), `*N`(자간), `$N`. 렌더링되지
  않으며 아래 규칙에서 **제외**된다. 원문과 토큰이 일치해야 한다(`kitae check` 마크업 정합).

## 1. 문자 집합 [원칙 1·7 + 추가]

`ko` 에 올 수 있는 문자는 아래뿐이다. 그 밖의 문자는 `kitae check` 가 FAIL 로 잡는다. [추가]

| 부류 | 문자 | 적는 법 | 주입 |
|---|---|---|---|
| 한글 | 완성형 음절 | 그대로 | 코드페이지 셀 |
| ASCII 문자·숫자·기호 | U+0020~U+007E | **ASCII 코드 그대로** (화면 모양과 무관) | 엔진이 1바이트 글꼴을 못 다루므로 **안전한 2바이트 영역에 재할당** |
| 공백 | `' '`(U+0020) | 어절 사이 공백 | 재할당 셀, 어절 폭 |
| 칸 맞춤 공백 | EN SPACE(U+2002)·EM SPACE(U+2003)·FIGURE SPACE(U+2007, 숫자 폭)·FOUR-PER-EM SPACE(U+2005, 6px) | 정렬·여백·숫자 자릿수 패딩에만. FOUR-PER-EM 은 반각 단위로 안 맞는 라벨의 반 EN 보정(제목 `시스템 설정`, 9/19) | 반각·전각·숫자 폭·6px 셀 |
| 전각 로마자 | `Ａ`~`Ｚ`·`ａ`~`ｚ` | **고정폭 영역**에서만 (`Ａ 버튼`, `Ｂ 버튼`) | 고정폭 셀 |
| 기호 | `『』「」・―’○△▼☆◎♂♀●〒§※■□♪×` 등 ASCII 에 없는 것 | 그대로 | 기호 셀(여백 없음) |
| 단위 `km²` | `²`(U+00B2) | 가이드 면적 표기 | `k` `m` 은 ASCII 셀, `²` 는 글꼴 전진폭(9) 셀. `㎢` 는 Plex 글리프가 44px 라 안 쓴다 |
| 마크업 | `@ & % * $` | 원문 토큰 그대로 | 렌더링 안 됨 |

- U+3000(전각 공백)·전각 숫자(`０`~`９`)·전각 기호(`．，！？：－～＝（）＜＞`)는 **쓰지 않는다**
  — 예외는 `／`: ko 에서 ASCII `/` 는 12px, 전각 `／` 는 24px 선택지 구분 기호(글리프는 같고 폭만 다르다, 9/19 정책)
  — 전부 ASCII 로 적는다. [원칙 1]
- **마크업과 겹치는 문자는 ASCII 로 적을 수 없다.** `% & * @ $` 가 글자로 필요하면 전각
  `％ ＆ ＊ ＠ ＄` 로 적는다(현재 `％` 9곳·`＆` 6곳). [추가]
- 가나는 `ko` 에 남을 수 없다(미번역 흔적, 예 TRFKARAOKE `?オプション`). 장음 `ー`(대사 114곳)만 예외.
  한자·키릴·그리스·로마숫자(`ⅠⅡ`)는 게임 글리프(24)로 **허용** — 퀴즈의 지명 읽기 문제,
  `留根算酢(르네상스)` 같은 말장난, 타냐의 러시아어가 의도적으로 쓴다. `ko` 가 원문과 같은
  항목(미번역 키, KITAE `主人公名前`)은 검사하지 않는다. [추가, 2026-09-18 조정]

## 2. 공백 [원칙 2·3·4 + 추가]

편집기에서 구분: `.vscode/settings.json` 이 Gremlins tracker 로 EM(빨강)·EN(파랑)·그 밖(주황)을 칠한다.

1. 어절 사이는 `' '` 하나. U+3000 은 쓰지 않는다.
2. **`.`·`,` 뒤에는 공백**을 둔다. 문장(줄·문자열)의 끝이면 붙이지 않는다(trim). [원칙 3]
3. [추가] `! ? :` 도 같은 규칙을 따른다(현재 `！` 3,293·`？` 3,385 — 뒤에 곧장 글자가 오는 경우가
   대사에 1,000곳 넘게 있어 일괄 변환 때 공백을 넣어야 한다). `！！`·`？！` 처럼 연달아 오면
   마지막 것 뒤에만.
4. [추가] **토큰 안의 `. , : / -` 는 구분점이 아니다.** 숫자·라틴 사이에 있으면(소수점 `1.5`,
   시각 `12:31`, 날짜 `2026/09/11`, URL, 전화번호 `070-…`) 공백을 넣지 않는다.
5. 괄호·따옴표: 기호 자체에 여백이 없으므로 띄어쓰기가 필요하면 **텍스트에 공백을 적는다**.
   [원칙 4] [추가] 자동으로 넣지는 않는다 — 한국어는 닫는 괄호·따옴표 뒤에 조사가 붙으므로
   (`『책』을`) 번역자가 적은 공백을 그대로 둔다. 괄호 안쪽에는 공백을 두지 않는다.
6. 칸 맞춤(가운데 정렬, 표의 열)은 EN SPACE/EM SPACE 로만 한다. 어절 공백을 여러 개 늘어놓지
   않는다. [원칙 2]
7. [추가] 줄 끝 공백은 없다(trim). 다만 §5 의 보호 항목은 예외.

## 3. 숫자·영어 [원칙 6·7 + 추가]

1. 숫자는 ASCII `0`~`9` 로 적고 **고정폭**으로 그린다. [원칙 6]
2. 영어는 두 영역으로 나눈다. [원칙 7]
   - 고정폭 영역 → 전각 로마자. 버튼·키 이름(`Ａ 버튼`·`Ｂ 버튼`·`Ｌ`·`Ｒ`), 단독 알파벳 라벨.
   - 가변폭 영역 → ASCII. URL(`http://…`), 영문 단어·문장(`You're welcome`), 상호(`TOP'S`),
     형식명(`F-15J`, `JR`).
   [추가] 어느 쪽인지는 단어장(`wordbook.json` `rules`)에 목록으로 둔다. 목록에 없는 라틴 문자열은
   가변폭(ASCII)이 기본.
3. [추가] 숫자와 단위는 붙인다(`20마리`, `4번`). 날짜는 기존 규칙대로 `8월 1일`(월·일 사이 공백,
   범위 `1월 1~3일`, 연호는 서기).

## 4. 글리프 수·줄 길이·타이밍 [원칙 5·8 + 추가]

1. 글자 수는 **바이트가 아니라 렌더링될 글리프 수**다. [원칙 5]
2. 합자: `". "`·`", "`·`" ("` 같은 두 글자를 글꼴 하나(셀 하나)에 넣을 수 있다. 텍스트는 두 글자
   그대로 적고, **주입기가 합자 셀로 바꾼다.** 원래 문자와 합자가 모두 글꼴에 들어간다. [원칙 4]
   [추가] 합자 목록은 한 곳(`widths.py`)에 두고, 줄 끝 trim 뒤에 적용한다(`". "` 가 줄 끝이면 `"."`).
   후보: `". "` `", "` `"! "` `"? "` `": "` `" ("` `") "`.
3. `%주인공이름%`(`&主人公名前&`)은 **8글리프**로 센다: 성 4 + 공백 1 + 이름 3. [원칙 8]
4. [추가] 줄 길이 한도는 두 가지를 다 만족해야 한다: (a) 엔진 레코드 한도 **25글리프**
   (`vw_extension=false`; 켜면 62), (b) 화면 폭 **600px**(가변폭 합산). `kitae check` 가 둘 다 본다.
5. [추가] MTG 타이밍(`mtg.py display_len`)의 글자 수도 글리프 수다(합자 1, 이름 토큰은 엔진이
   런타임에 치환하므로 그대로).

## 5. 보호 항목 — 규칙을 적용하지 않는 텍스트 [추가]

엔진이 **바이트 단위로 조립·해석**하는 UI 문자열은 §1~§4 를 적용하면 깨진다. JSON 항목에
`"fixed": true` 를 두어 변환기·검사기가 건너뛰게 한다(플래그 이름은 구현 때 확정).

- 서식 템플릿·색인 접두: `@００００００００`, `0ローズヒル南平岸`(첫 글자 = 지역 번호), `\t札幌駅南口`.
- 엔진이 조각으로 조립하는 문자열: `月`·`日`·시간대(`　朝`…), `１`·`０`(숫자 조립).
- 고정 폭 필드: 15개 전각공백(저장 슬롯 장소 필드), 가운데 정렬용 앞머리 공백이 든 메뉴 라벨
  (`   最初から`, 가이드북 지역 행), `　　保存日時　`.
- **24px 고정 피치 선택지 행**(시스템 설정 `표준／高速` 등): 엔진이 글자 번호×24 로 커서 상자를
  두므로 원문과 같은 칸 수로 쓴다 — 구분 기호는 `／` U+FF0F(ASCII `/` 와 같은 모양, 폭 24 셀), 공백은
  EM SPACE, 숫자는 전각(`fixed`). 2026-09-18 사용자 결정(코드 패치 대신 글리프로 맞춤).
- 그 밖에 `ja` 에 `? ' _ | " [ { $ ^ \` 같은 코드성 ASCII 가 있는 항목(ui 에 413·64·63·32… 개) —
  형식 문자열이므로 손대지 않는다.

## 6. 주입기 규칙 [원칙 1·4·6 + 추가]

1. **단일 출처**: 셀 배정은 `data/codepage.json`, 폭은 `kitae/build/widths.py`. 글꼴 굽기·폭표·검사기가
   같은 값을 본다.
2. ASCII 재할당 영역은 cp932 사용자 정의 페이지(현재 한글 페이지 뒤)에 **연속으로** 둔다. 엔진의
   1바이트 처리(고정 12px, `CTRFTextOut`)를 거치지 않게 한다.
3. 기호 글꼴은 모던 글꼴 그대로: 앞뒤 여백(사이드베어링 보정)을 넣지 않는다. 지금의 `。`=잉크+9,
   `．`=잉크−1, `『` 좌+1/우−1, `」「」` 12 고정은 **없앤다** — 여백은 텍스트의 공백이 맡는다.
4. 폭: 숫자 고정폭(값은 굽기 때 한 번 정함), 라틴 가변폭(잉크+여백), `' '` 어절 폭(현 9px),
   EN SPACE 12px, EM SPACE 24px, `・` 고정폭 가운데 정렬(말줄임 `・・・`·나열 겸용, 31,035곳).
5. [추가] 폭표(.ktrw)는 디스크 익스텐트 때문에 1,024B 안이다(페이지맵 256 + 하위표 2장). 재할당
   페이지가 늘면 하위표 배정을 다시 정한다.

## 8. 현재와의 격차와 작업 순서
