# ENC2 압축 포맷 — 해독 완료

해독일: 2026-08-05 · 구현: [tools/enc2.py](../tools/enc2.py)

## 결론

ENC2는 **12비트 절대 위치 + 4비트 길이의 LZSS**다. 두 갈래(알려진 평문 분석 / SH-4
역어셈블)로 독립 도출한 결과가 완전히 일치했고, 디스크상의 **ENC2 엔트리 3,442개
전부가 예상 크기로 정확히 복원**된다.

## 엔진 측 구현 (TRFSCORE.DLL, image base 0x10000000)

`.pdata`(RUNTIME_FUNCTION 1,798개)로 함수 경계를 확정한 뒤 추적한 위치:

| VA | 내용 |
|---|---|
| `0x100017d0` | 아카이브 청크 디스패처 (ENC0/ENC1/ENC2 태그 비교) |
| **`0x10002d54`** | **`CTRFLzss::Decompress(this, src, srcLen, dst, dstLen)`** |
| `0x10002b50` | `CTRFLzss::Compress` |
| `0x10002a7c` | `CBitStream::GetBit` |
| `0x1004c748` | `ITRFCompless` vtable (slot 3 = Compress, slot 4 = Decompress) |
| `0x1002299c` | CTRFLzss 생성자 — 윈도우(this+8, 0x1000바이트) 0으로 채움 |
| `0x100507e0` | 클래스 레지스트리 (20바이트 레코드) |

클래스명 문자열로 인코딩 정체 확인: **ENC0 = 무압축(`ITRFCompless`), ENC1 =
`CTRFHuffman`(이 디스크에선 미사용), ENC2 = `CTRFLzss`**.

## 포맷 명세

- **비트 순서**: 바이트 내 **LSB first** (바이트 0의 비트 0이 첫 비트). 바이트는 순서대로.
- **다중 비트 값**: **MSB first** 조립 (`v = (v << 1) | bit`).
- **윈도우**: 4096바이트 링 버퍼, **0으로 초기화**. 쓰기 커서는 **1에서 시작**
  (Okumura 표준 LZSS의 `N-F` 초기화나 0x20 채움이 **아님**).
  출력 i번째 바이트는 윈도우 위치 `(i+1) & 0xFFF`에 저장된다.

```
반복:
  flag = 1비트
    1 → 리터럴: 8비트 값을 출력
    0 → 매치:  12비트 src   ← 윈도우 내 "절대 위치" (뒤로 거리 아님!)
                             src == 0 이면 스트림 종료
                 4비트 len-2 ← 길이 2~17
               k=0..len-1 에 대해 window[(src+k) & 0xFFF] 출력
  출력한 모든 바이트(리터럴/복사 불문)를 커서 위치에 기록하고 커서 +1 (mod 4096)
```

복사는 자기가 쓰는 윈도우를 그대로 읽으므로 겹치는(run-length) 매치가 자연히 동작한다.

### 주의점 (인코더 작성 시 필수)

1. **종료 표지 필수**: 엔진 복호 루프에는 **출력 길이 검사가 없다**. `src == 0`을 만나야만
   멈춘다. 실측(154개 스트림): 112개가 마지막 바이트 직후 명시적 종료 표지를 갖고
   나머지 42개는 그 지점에서 비트가 소진된다. **스트림 중간에 `src == 0`이 나온 사례는 0건.**
2. **`src = 0`을 매치로 내보내면 안 된다**: 커서가 4096바이트를 한 바퀴 돈 뒤에는 위치 0도
   후보가 되는데, 이를 내보내면 파일 중간에서 복호가 끝나버린다.
3. **4바이트 정렬**: 압축 청크 크기는 항상 4의 배수 (측정 154/154).
4. 원본 크기는 스트림에 없다 — CAB `INFO` 레코드의 `stored_size`에서 온다.
   (다만 종료 표지가 정확히 끝에 놓이므로 포맷 자체는 자기종결적이다.)

## 구현 상태

- `decompress(data, out_size)` — 디스크 전체 **3,442/3,442** 성공, 실패 0.
- `compress(data)` — 종료 표지·`src=0` 회피·4바이트 패딩 반영. 왕복 테스트 **152/152** 정확.
  압축률은 Hudson 인코더 대비 약 **+2%** (탐욕적 매치 탐색이라 최적은 아니나 실용상 무해).
