# 플롯 구조 지도

작성일: 2026-08-05 · 생성 도구: [tools/plotmap.py](../tools/plotmap.py) · 데이터: `dump/plotmap/scenes.tsv`

ENC2 해독으로 `SCN/INIS.CB` 전량이 열리면서 **씬 1,579개 / 플롯 48개**의 전체 구조가 확보됐다.

## 1. 플롯 = 시나리오 파일 (P00~P47)

`SCN/INIS.CB`의 `PLOTS.INI`가 플롯 번호 ↔ 시나리오 이름을 정의하고, 이는
`MISSION/PLOT.TAB`의 SMF/EB 파일 ID와 **정확히 일치**한다. 즉 플롯 하나 = SMF 1개 + EB 1개.

| 플롯 | 내용 |
|---|---|
| **P00 = hanyou(汎用)** | **범용 씬 풀** — 날짜 없이 `시간대/장소`로만 키가 잡힌 재사용 씬 60개. 자유행동의 기반 |
| P01~P24 | 여름편 개별 루트: 琴梨(P01–P06), 鮎(P07–P09), 葉野香(P10–P11), 梢(P12–P13), 由子(P14–P16), 薫(P17–P19), ターニャ(P20–P21), めぐみ(P22–P24) |
| P25~P41 | 겨울편 루트 (각 캐릭터 `冬1`/`冬2` 2편 구성) |
| P42 game / P43 風呂 / P44 歌詞 / P45 uranai / P46·P47 風呂冬 | 미니게임·목욕·노래방·점술 등 공통 이벤트 |

`_cbs` 접미사 플롯(P06, P09, P11 …)은 50~60줄짜리 소형으로, 선물/리액션 처리 등
**공통 서브루틴** 성격이다 (예: `P06S001E00=＠プレゼント処理`).

## 2. 씬 = 시공간 좌표 (핵심 발견)

씬 제목이 곧 **트리거 조건**이다. 슬래시 구분 필드로 파싱된다:

```
○８月２日／午前／北海道庁／道庁前（ひとりの場合）
  └날짜  └시간대 └장소     └세부위치  └분기조건
```

- **시간대**: 朝 → 午前 → 昼 → 午後 → 夕方 → 夜 (하루 6구간)
- `午前｜午後` 처럼 **복수 시간대 허용** 표기 존재 (겨울편 105건)
- 겨울편 12/30은 시간대 대신 **`琴梨と札幌デート` 같은 동행 루트**가 그 자리에 들어간다 → 종일 데이트 구조
- 분기 조건은 괄호로: `ひとりの場合` / `琴梨と一緒の場合` (동행 여부로 씬이 갈림)

## 4. 진행 방식 (구조에서 도출한 모델)

```
날짜 + 시간대 진행  ──►  플레이어가 장소 선택  ──►  (날짜, 시간대, 장소, 플래그)에
   (KITAE.DLL의                                      맞는 씬 P##S### 기동
    IKitaTimeAction /                                  │
    IKitaLocation)                                     ├─ 루트 플롯(P01~P41)에 해당 씬이 있으면 그것
                                                       └─ 없으면 P00(汎用)의 시간대/장소 씬으로 대체
```

- 씬 기동은 `TRFSCENELAUNCH.DLL`(`SCN/Plots.Ini`, `Plots.scn`, `PlotSelect`)이 담당.
- `[contain]` 섹션은 씬별 **선행 로드 리소스 목록**(배경 BGn/BGf, 음악 M, 효과음 SE,
  캐릭터 스프라이트 HKn/KAn/… )이다. 흐름 정보가 아니다.
- `[P##S###]` 섹션의 `E00, E01…`은 씬 내부 **이벤트 슬롯**이며 값은 개발자 주석
  (`＠シーン終了`, `＠ＦＯ`=페이드아웃, `＃ＳＥ００１`=효과음 지정 등). 총 3,750종.
  실제 동작은 EB 바이트코드에 있다.

## 5. 메시지 창 ↔ 텍스트 대응 (실측 확인)

실제 화면 캡처와 대조한 결과, **메시지 창 한 개 = 연속된 SMF 문자열 2개**였다.
예: 오프닝의 母 대사는 `KOTORI_01.SMF #3` + `#4`가 한 창에 2줄로 표시된다
(플롯 P01, 씬 `P01S000 イントロダクション・１`).

이는 `MTG.CB`의 타이밍 데이터로 **증명된다**. `<script>.SET`의 `CTRFMsgTiming` 객체는
**표시 글자 1개당 (u8,u8) 쌍 하나**를 갖는다. 창 #2의 타이밍 쌍 수 36 = 문자열 #3(14자)
+ #4(22자). 오프닝 9개 창 전부 글자 수가 정확히 일치한다.

| 창 | 문자열 | 글자 | 음성 |
|---|---|---|---|
| 1 | #1+#2 | 23 | a0013 |
| 2 | #3+#4 | 36 | A0014 |
| 3 | #5+#6 | 25 | A0015 |
| 6 | #11 | 16 | a0018 |
| 9~ | #15… | — | (없음) |

재구성 도구: [tools/windows.py](../tools/windows.py) (`python windows.py KOTORI_01`)

### 번역 시 반드시 지킬 것

1. **2줄 단위로 묶어 호흡을 맞춘다.** 한 줄만 길어지면 창 밖으로 넘친다.
2. **`.SET` 타이밍은 글자 수에 종속된다.** 번역문 길이가 바뀌면 해당 창의
   `CTRFMsgTiming` 쌍 개수도 새 글자 수에 맞춰 재생성해야 한다. 안 그러면 음성 동기
   표시가 어긋난다. (이것이 EB보다 더 빡빡한 실제 제약이다.)
3. 타이밍/음성이 **없는** 창은 나레이션·독백이다. 있는 창은 실제 발화다.

### 창↔문자열 매핑은 데이터에 있다 (2026-08-06 확정)

추론할 필요가 없었다. **모든 `.SMF`는 문자열 뒤에 `.MSG` 청크를 갖는다**:

```
".MSG" u32 size          size == 8 × 창 개수
반복(창마다): u32 line_count, u32 byte_offset
```

`byte_offset`은 `.STR` 헤더(12바이트) 이후 문자열 블록 내 바이트 오프셋이다.
즉 창은 그 위치의 문자열부터 `line_count`개를 연속으로 표시한다.

검증: 41개 스크립트 **9,670창 전부가 .MSG 테이블을 가지며**, MTG 타이밍과의
글자 수 대조에서 불일치 22건(0.23%)만 남는다. KOTORI_01은 **0건**.

줄 수 분포(유성 창 기준): 1줄 50, 2줄 55, 3줄 67 — **3줄이 가장 흔하다.**

### 인라인 마크업 (번역 시 보존 필수)

메시지 문자열에는 표시되지 않는 제어 표기가 섞여 있고, 타이밍 글자 수에서 제외된다:

| 표기 | 뜻 |
|---|---|
| `@S@` … `@P@` | 재생 제어 (속도/일시정지 추정) |
| `&主人公&`, `&主人公名前&` | 실행 시 플레이어 이름으로 치환 |

`windows.py`의 `display_len()`이 이를 제거한 길이를 계산한다.

## 5-1. 화자 식별 — 현재 가능한 범위

- **화자 이름은 데이터에 있다**: `north01.sym` 첫 섹션에 89개 심볼
  (문자열은 오프셋 24부터 시작. `文字`=0, `独白`=1, `琴梨`=2, **`陽子`=3**, `薫`=4, `主人公`=5 …).
- 다만 **게임 화면에는 화자 이름 표시가 없다**(캡처로 확인). 즉 저작 도구용 메타데이터다.
- **씬 단위 화자 목록은 확보했다 (2026-08-06)**: SCV의 `CTRFLipControll` 객체가
  `NAME` 필드에 화자 이름을 문자열로 갖는다. 예) `P01S000` → `[文字, 琴梨, 陽子]`,
  `P01S001` → `[独白]`. 전 1,104씬에서 **89종**이 나와 `north01.sym` 심볼 수와 정확히 일치한다.
  파서: [tools/clss.py](../tools/clss.py)의 `named_field()`.
  → 어느 씬에 누가 등장하는지는 이제 자동 추출된다. 다만 **대사 한 줄 단위**의 화자 지정은
  여전히 미해결.
- EB에서 "메시지→화자" 테이블은 찾지 못했다. 고정 간격 u8/u16 배열로 화자 인덱스 수열
  (`文字,琴梨,陽子,陽子,琴梨,…`)을 전수 검색했으나 **일치 0건**. 화자 지정은
  이벤트 디스패치 테이블 `(event_id, code_offset)` 뒤의 옵코드 안에 있다.
  SCV의 `ElmScript`는 `(시각 u32, 명령 u32)` 키프레임 타임라인이라 메시지 참조가 없다.
- **실용 대체 단서 — 음성 파일명 대소문자**: 오프닝 8개 창에서
  소문자 `a####` = 琴梨, 대문자 `A####` = 陽子 로 **8/8 일치**했다.
  성우별 납품 배치가 그대로 파일명 표기에 남은 것으로 추정된다.
  전체 코퍼스는 `a` 2,741 / `A` 3,448로 양분되므로 **89명을 구분하진 못한다** —
  한 장면에 화자가 둘일 때 쓰는 보조 단서 정도로만 신뢰할 것.

## 6. 아직 EB에 남은 것

씬 **내부**의 분기(선택지, 플래그 판정, 호감도)와 씬 간 실제 천이 조건은 EB 바이트코드에 있다.
씬 제목의 괄호 조건이 그 힌트를 주지만, 정확한 판정식은 `CKitaEvent`(KITAE.DLL) 옵코드
해석이 남아 있다 — [SCRIPT-SYSTEM.md](SCRIPT-SYSTEM.md) §6 참조.
